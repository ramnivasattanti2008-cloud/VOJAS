## Root-cause groups

### A. Broken generated Prisma boundary: TS2305

The Prisma schema contained all seven concepts, but the generator output was configured under `packages/db/node_modules/.prisma/client`. The hoisted `@prisma/client` resolved by the workspace read `node_modules/.prisma/client`, whose declarations were stale/minimal and did not expose the schema models. This caused the missing exports and removed contextual types from Prisma query results.

## Fixes applied

1. Changed the Prisma generator output in `packages/db/prisma/schema.prisma` from `../node_modules/.prisma/client` to `../../../node_modules/.prisma/client`, matching the hoisted `@prisma/client` resolution used by the workspace.
2. Regenerated Prisma with `pnpm db:generate`.
3. Changed `apps/api/src/routes/sectors.ts` to import `SectorConfig` from `@vojas/domain` instead of the frontend-oriented `@vojas/api-client` package.

No `any` authorization, financial, satellite, or project-data bypass was introduced. No schema fields or domain concepts were invented.
